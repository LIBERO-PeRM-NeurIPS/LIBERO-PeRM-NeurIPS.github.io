01Abstract

From “Can the robot do the task?” to “Can it do the task my way?”

Personalization is essential for general-purpose robots to transition into household environments and achieve true practicality. While general robotic manipulation has been extensively studied, personalized robotic manipulation (PeRM) lacks a controlled benchmark for separating task completion from preference satisfaction. We introduce LIBERO-PeRM, a benchmark for preference learning in embodied agents. LIBERO-PeRM studies five questions: 1) how policies follow preferences in zero-shot settings; 2) how they learn single preferences from demonstrations; 3) how efficiently they acquire preferences as demonstrations increase; 4) how learned preferences generalize across layouts and tasks; and 5) how policies compose preferences and behave under conflicts. We propose a controlled formulation and taxonomy of observable preferences in simulation, covering motion, skill, and user-profile choices. This formulation is restricted to language-expressible preferences that can be instantiated in LIBERO without changing the task goal, evaluated automatically, and reused across tasks. Building on LIBERO, our procedural pipeline generates paired demonstrations with and without preferences. We create five task suites (312 tasks) with high-quality demonstrations, rich metadata, and preference-satisfaction metrics. Experiments show that current VLA policies struggle with zero-shot personalization, while SFT makes preferences learnable. Mixed training achieves better no-preference retention than sequential adaptation and improves performance with contextual prompts compared with preference-only training, but can weaken motion-preference learning; preference generalization, decomposition, and conflict handling remain difficult.

02Preference formulation

Three preference levels, 37 single preferences

A preference is not a separate goal. It is a conditioning signal that biases how the task is carried out, and it is defined by the part of execution it constrains: the motion, the skill, or the subtask-level choice. Pick a level and a preference below. Each one comes with two layouts, shown with and without the preference and scored by its own metric.

03Benchmark construction

A procedural pipeline that treats preferences as controllable variables

Starting from a LIBERO layout, a task and a preference, the pipeline produces a preference-ready scene, paired demonstrations with and without the preference, subtask metadata, and the metric that scores the preference.

Stage 1

Preference selection and layout modification

A VLM makes the smallest edit that lets the preference be acted on. Motion and skill preferences leave the layout and task language untouched, and the VLM only picks the target, such as the object to avoid. A user profile adds what it needs, for example a red twin of an object, and the task language is abstracted so one sentence covers both behaviours.

Stage 2

Preference-conditioned generation

A VLM writes a no-preference plan and a preference-conditioned plan. A library of heuristic skills, each built from one human demonstration plus an OMPL planner over randomized initial states, turns the plans into trajectories. A user profile changes the plan, a skill preference changes which skill is called, and a motion preference changes the skill's parameters.

Stage 3

Satisfaction metric generation

Each preference gets an explicit metric. Motion preferences are scored from trajectory quantities, skill preferences at key waypoints, and user profiles from the executed subtask plan. Scores map to a four-level label so that all three levels report on the same scale.

06Evaluation protocol

Task success and preference satisfaction, reported separately

A policy can finish the task while ignoring the preference. Two metrics keep those apart, and preference satisfaction only counts on episodes where the task succeeds.

SRTask success rate
SR = (1/N) Σn 𝟙[ G(τn) ]

Whether the task goal is reached, with or without a preference in the prompt.

SAPreference satisfaction
SA = (1/N) Σn 𝟙[ G(τn) ] · dn

Each episode gets a discrete satisfaction label dn ∈ {0, ¼, ¾, 1}. A failed episode contributes zero.

Gen.Three generalization settings
in-domain → task / layout → preference-level

In-domain keeps tasks, preferences and layouts with small object-position changes. Task-or-layout changes one of them. Preference-level changes the task under an unseen layout.

Motion

Scored from the trajectory

Physical quantities of the path: time per subtask, end-effector acceleration, height during lateral moves, straightness of the carry segment, clearance from a named object, rotation while moving.

Skill

Scored at the skill's key moment

The pose at the grasp or at the release: where the gripper sits relative to the object, its approach angle, how the object is set down or let go, whether it was lifted at all.

User profile

Scored from the executed subtask

Which candidate the policy commits to: the object it picks up first, or the target it places the object at, checked against what the profile implies.

07Experiments

Five questions, five findings

Six VLA policies are evaluated zero-shot: OpenVLA-OFT, π0-fast, π0.5, GR00T-N1.6, SmolVLA and UniVLA. Fine-tuning experiments start from π0.5, the strongest zero-shot baseline.

Q1

Zero-shot: policies finish the task and ignore the preference

Minimal layout edits keep no-preference success high, with π0.5 at 97.6%, so low satisfaction reflects preference following rather than a harder scene. On motion and skill preferences π0.5 succeeds 97.5% and 100% of the time but satisfies the preference only 24.4% and 25.0%. A user profile changes the target itself and drops π0.5 to 19.1% success.

Q2

Fine-tuning makes preferences learnable, and mixed training is a trade-off

LoRA fine-tuning on LIBERO-SinglePref lifts all-preference SR/SA to 85.0 / 82.5. Fine-tuning on LIBERO first and preferences second costs no-preference success, which falls to 52.3%. Mixing both in one run keeps it at 91.0% and holds up under rewritten prompts: 72.8 / 70.1 on LIBERO-ComprePref against 44.0 / 42.6 for preference-only training. The price is paid on motion preferences, where success drops from 90.0% to 66.9%, so mixing is not uniformly better.

Q3–4

Layout diversity helps more than extra demonstrations, and generalization stays hard

In-domain SR and SA track each other at every data scale: when the task succeeds, the preference is usually satisfied too. At a fixed budget of 2.25K demonstrations, spreading them over more layouts (L1 → L3) helps more than adding demonstrations per layout, and adding matched no-preference missions (L4) helps again without any new layout. Unseen layouts improve with scale. Unseen layouts with a different task do not.

Q5

Composition is partly learnable, decomposition is not

Trained on PA and PB separately, the policy composes PA + PB with 25.0% SR and SA. Asked to recover PB after training on PA + PB and PA, it reaches 37.5% SR and 0.0% SA: the task gets done, the target preference does not.

Q5

Conflicts degrade execution instead of being resolved

Under two conflicting preferences SR/SA fall from 73.0 / 63.4 to 66.0 / 47.8, and neither preference dominates (gap 11.3). When the preference argues against the task, following the task (33.3%) and following the preference (29.2%) are about as likely, and 37.5% of trials complete neither.
